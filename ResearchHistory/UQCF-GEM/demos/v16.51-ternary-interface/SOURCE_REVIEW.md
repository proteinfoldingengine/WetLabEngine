## Blocking findings

1. **Promised verifier-level omission RED was not established.** The preserved test_prospective_red.py invokes coverage.verify_identities directly on two string identifiers. It never calls verifier.verify and supplies no otherwise-valid certificate corpus. TEST_MANIFEST_RED.json candidly labels this a coverage-unit fixture, but PREREGISTRATION.md requires an otherwise-valid corpus with one identity removed and failure through the verifier. The helper RED is real evidence of helper behavior, but does not satisfy that stronger requirement. Preserve it; disclose the discrepancy; prospectively manifest a genuine verifier-level mutation RED and repaired GREEN, without pretending that a later run occurred before implementation. If chronology is part of the strict gate, record a prospective amendment and its limitation or leave that gate unmet.

2. **The full-palette control misses the critical order exception.** test_whole_palette_child uses reversed, inflated U with q=[2,1,1,1,2,2,2], k=4. By inspection its first two roots become {0,1,3} and {2}, while the third is P. The selected pair is (0,2), but its anchor is 0; applying x-first incorrectly to the full child would leave its order unchanged. Hence this test does not detect removal of the w[c]<k ordering exception. Use an explicit noninflated reversed compact state for the same profile: roots {3}, {2}, P, selected pair (0,2), anchor 3. Assert those facts and the resulting canonical descendants, alongside the no-full-child-transport assertion. Preserve or version the manifest before the affected execution.

3. **Failure outcomes lose the protocol distinction.** run_campaign.py writes status INCOMPLETE for every verifier exception. The protocol assigns construction failures, incorrect width/canonical feasibility, illegal steps, and overcost attempted paths to INTERFACE_NOT_PRESERVED; coverage/resource/provenance/review gaps are INCOMPLETE. Introduce explicit typed/classified failure reporting with the failed obligation and retained evidence. A certificate is already written before verification, which is appropriate. Neither outcome is a nonunit witness.

4. **Start-generation failures escape per-case retention.** producer.produce constructs initial(...) before its try block. A failed/invalid/unavailable frozen start would therefore abort generation without a retained per-case failure, and later identities would be absent. The protocol says not to discard invalid starts or failed cases. Capture start generation and normalization within each per-case failure boundary, retain each specification identity and its available input/attempt, and continue through the full frozen identity list. The independent verifier should reject recorded failures with the appropriate outcome rather than silently treating them as omitted data.
