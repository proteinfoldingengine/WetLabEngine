# Next validation gate — validate the mechanisms in the proof

This is a list of proof-derived obligations, not an approved implementation plan or a numerical result. The current deliverable is the reusable analytical interface and its independent review.

1. **Exact native feasibility.** Implement the compact 15-region feasibility definition and canonical order exactly as stated. An independent checker must reconstruct the admitted root-support domain and hitting minima. It must distinguish an infeasible palette from a failed constructor. Do not impose the ternary middle-target recurrence.
2. **Fixed-root clearance.** Validate proper-descendant replacement with both old and new labels already present at the child root. The existing attached whole-subtree transport routine has different preconditions and cannot be reused without accounting for this boundary. Check every interior coordinate and every primitive, including root-full states, leaves, and final root deletion.
3. **Cover reconfiguration.** Exercise target-bin-full displacement, a spare bin that is the moving label's current bin, zero-capacity/full-width children, duplicate occurrences during a transfer, and the completed-partition invariant. Check coverage and every capacity after each complement incidence, not just after complete transfers. Each iteration must fix a label without displacing a fixed one.
4. **Global excursion and phase discipline.** Check the parent after each lifted root move and every descendant coordinate after each clearance primitive. Recursive child normalizations may run only while the parent is exact. Preserve partial paths on failure. Separately reject the two unsafe old-transport examples from proof Section 9 as unit paths; they remain natively admitted sequences.
5. **Canonical and interface obligations.** Check minimum palettes, exact selected A_i* endpoint, compact union, attached contraction, simultaneous label/order equivariance, and four-child interfaces used by an enclosing call. Any nested cases serve these new interface obligations; further depth in already certified binary/ternary trees is not a research target.

Before implementation, write a concrete execution plan and a prospective, bounded validation protocol with exact identities, expected failure signatures, and stopping rules. Run numerical science/tests on GitHub only. Preserve genuine failing controls before implementing the relevant routine. Favor small exhaustive native boundary checks and explicit adversarial examples; a large directed passing-case count is not the acceptance criterion.

Implementation or certification status must remain separate from analytical acceptance. A failed chosen procedure is not a nonunit barrier. Any claimed nonunit obstruction needs native exact endpoints and a proof excluding every unit path.
