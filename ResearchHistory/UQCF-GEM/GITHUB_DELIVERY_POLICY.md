# Research delivery preference

The user has explicitly requested GitHub publication rather than local-file
handoffs. Publish research source, reports, numerical results, and usable viewing
assets to proteinfoldingengine/WetLabEngine. Give branch-specific source links
and verified release links; do not require the user to download files here or
perform manual uploads as the normal delivery path.

Keep exact source identity, executed test evidence, and physical claim boundaries
visible. A queued workflow is not success; a template is not a finished replay;
a regenerated archive is not proof of byte-exact preservation of older originals.
Existing archival gaps remain separately labeled rather than silently certified.

New work stays additive on research branches with draft PRs unless merging is
explicitly authorized. Do not change repository visibility, old scientific
snapshots, or the main branch as a side effect of publication. Computational
working files are not user-facing deliverables.
