# The historical star writer reads the pruned donor before editing an empty receiver

Two rows of the original v16.43 scientific archive contain a source pruning followed immediately by an edit at a different index. Both occur within one invocation. The writer reads the donor's surviving leaves from the same mutable indexed cover that it just edited. Its next instruction gives the surviving leaf to an initially empty receiver. A one-bit intervention in the running computation changes which leaf reaches the receiver. The earlier v16.45 junction-rise example has the opposite causal property under the same test.

## Two recorded executions

The tree is a root with leaves 1, 2 and 3. Each view contains the root. The ordered indices are a reference, receiver B and donor A. A starts with leaves 1 and 2. B has neither. The reference holds leaf 3 and one of A's two leaves. This is a different tree and preparation from the seven-site fork. One reference membership moves from leaf 1 to leaf 2 between the two rows, changing two incidence bits. Neither the source's initial view nor the receiver's initial view changes.

## One-bit control inside the same invocation

At the first deletion the checker restores only the donor bit just before the original routine appends its snapshot. The initial state, H, index order, program location, and all later instructions are the same as in the corresponding unmodified run. The original later code executes against this changed buffer. In both controls it now reads [1,2] from A and B receives leaf 1 and then leaf 2 in the transfer loop. For row 184, B's very first acquisition changes from leaf 2 to leaf 1. For row 232 the added second leaf distinguishes the transfer from its original singleton even though the first leaf stays the same. Restoring the bit intervenes on the donor read's input. It is not a second original campaign history.

In row 232 the compressed history of B alone is the same in both runs; which leaves the transfer loop copies still differs. Row 184 does change B’s first edit.

Both restored-bit histories consist of admitted star states and elementary graph edits after the deliberately repeated state is ignored. They need not satisfy the canonical endpoint requirement. The observed comparison of rows 184 and 232 uses two unmodified original executions that both do satisfy it. The control isolates the donor bit from the upstream difference in reference membership.

## What the seven-site rise can predict

In the v16.45 fork writer, an emitted deletion of a left junction has only one code location: cleanup after normalizing the left star. Let a be the deleting index, k the number of indices and s the initial left-star cover number. The left palette consists of the first s indices. A left-junction deletion implies a≥s. Each later index still holds its left junction and must delete it next, in increasing order. After these removals the writer adds the right junction, again in increasing order, to every index missing it in the post-event state. This prefix is determined by the certified event site, donor rank, indexed masks, and the fact that the event was emitted by this running writer. The number of lower-ranked views still holding the left junction recovers s. No externally selected restart or supplied saved palette is needed to *predict that prefix*. The prediction ends before right-star normalization.

The actual (15,1,115) → (15,1,113) rise is emitted at index 2, the last index. Indices 0 and 1 lack their right junctions. The predicted next two states are (31,1,113) and (31,17,113), exactly the stored path. The root-only middle receiver therefore acquires its right junction as predicted. The assertion depends on the source's provenance in this invocation.

Predictability of a subsequent edit does not show that the source deletion carried the distinction. Restore only the donor's just-deleted left junction before the snapshot in that running fork writer. The succeeding left cleanups concern other indices. The right-side code reads only right-subtree bits and the previously computed palettes. Consequently every later mask is exactly its original value with that single donor bit restored. Every other index has the same history. The checker performed this intervention separately at all 98 left-junction deletions on the 139 stored paths across the six v16.45 fork domains. Eighty-one prefixes contained further edits. They include 30 left deletions and 102 right additions counted over the event occurrences, with shared suffixes counted again. Every predicted prefix matched, and all 98 interventions preserved every other index's history.
