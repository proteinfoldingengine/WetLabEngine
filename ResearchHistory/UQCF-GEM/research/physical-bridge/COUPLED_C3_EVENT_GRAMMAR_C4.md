## Exact mathematical typing, within the common labelled-support carrier

For a C3 pair-root carrier H=(V,E), let its indexed root family be R=E. For each e in E, a labelled support S_e is a subset of a finite palette P. Thus a C3 core state is already an indexed tuple (S_e)_{e in E}, a special case of the indexed support tuples used in A11.

A C3 primitive that inserts x into root e is precisely the incidence event A(e,x) when x is absent; removal is D(e,x) when x is present. These are the same **single-incidence toggle syntax** as the A11 endpoint-event notation. For any finite successful edit sequence, the map between these two event descriptions preserves the addressed root, label, sign, and resulting labelled support tuple at every prefix. This is a definitional identification on the shared mathematical carrier, not a cross-domain physical representation map.

The original C3 floors f_e and band 3<=tau<=4 can be evaluated on those same support tuples. This does **not** make every syntactically valid A11 event C3-admissible: each prefix must still satisfy the C3 floors/band, and universal safety over the original hidden-completion fiber additionally requires its protected hidden-slice and original-footprint conditions. Conversely, C3 NOOP is an allowed *resolved request outcome*, not an incidence toggle and not an A11 proof-only marker. A11's sigma/rho certificate markers have no native incidence effect and cannot serve as observer events.

An A11 endpoint-only event set contains only incidences in source/destination symmetric difference; C3 paths can use temporary incidences and repeated toggles. Thus the exact identification is at the level of individual addressed toggles, **not** equivalence of their admissible path classes or X63 certificate completeness.

But neither notation produces a native source event with provenance-certified structural lineage identity, an actual resolved successor, or an accessible retained marker increment.
