# The stock automatic exact-profile repair does write to untouched rows, but is not an online reaction

I tried the existing clip/shadow writer rather than adding a second label command to the M4 input. This is a new six-row diagnostic with stock v16.54 code, not original archived behavior or a claim of native delivery.

Prepare support rows [[0,2],[0,2],[1,3],[1,4,5],[2,3],[2,4]], floors [1,2,1,1,1,1], k=6 and q=2. Supply a **single** ordered clone pair (0,1). Its degree-free primitive path edits only rows 0 and 1. The first replacement takes row 0 from {0,2} through {0,2,3} to {0,3}. Its deletion of 2 raises the exact hitting number from two to three; the subsequent addition of 4 at row 1 restores it to two. The recorded preliminary hitting word is 2,2,3,2,2,2. The three-label peak has lexicographically selected minimum cover (0,1,2). The existing producer automatically invokes clip, which applies shadow with that cover's first two labels. By its original packet rule, it adds 0 to each of the two previously untouched rows holding 1. No second pair, address, or receiving support is passed. The producer returns an exact hitting-number-two path that contains both added supports.

**Ordering check.** In the returned path both remote additions occur BEFORE the deletion that gave rise to the raw peak. The exact returned event prefix is row 0 +3, row 2 +0, row 3 +0, row 0 -2. Both remote additions are undone and the raw and output endpoints agree. The whole preliminary plan, including that deletion, is available before clip runs; clip then rewrites a prefix of the path. This is a real internal path-construction dependency, not a remote update caused online by an already-committed source event. It does not retain an endpoint distinction there.

The ordering is not an accident of these indices: in a clip sweep, the first peak is entered in the preliminary path by a deletion (a gain cannot raise tau), and the preceding vertex is below that peak. No previously unchanged vertex below the peak is shadowed at that sweep. The join into the first shadowed peak performs every new addition before its deletions. Any new unaffected-row additions in this join therefore occur before the raw deletion whenever it survives in that join. This statement is scoped to that first-peak join in the sweep, not to later layers or every nested mechanism.

**Controls.** Inserting 4 in row 1 at entry retains the same source row-0 replacement and raw receiver priors while removing the peak, so neither receiver is ever changed. Using the unchanged full prior but another single pair (0,3) likewise cuts source label 2, has no peak and writes neither receiver. The stock producer and independent verifier pass both controls; every emitted frame has exact cover two. The six catalog geometries and all their row shifts were also reconstructed (37 original M4 identities up to tag provenance, 25 ending at the target); none uses a nonempty clip sweep. The diagnostic does not retrofit the automatic write into an archived record.

Conclusion: stock software can select an auxiliary edit automatically in this prepared setup, but its mechanism is a global path rewrite with an unchanged endpoint, not the missing forward enactment or receiver custody. It is not a substitute for the separately accepted PR180 persistent receiver writes, whose own command sequence remains supplied.
