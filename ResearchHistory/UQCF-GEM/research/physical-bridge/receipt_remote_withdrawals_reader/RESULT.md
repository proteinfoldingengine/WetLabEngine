# The original witness verifier read four event fields

Two original v16.27 execution paths read different things. The campaign runner opened historical-producer.log and compared four totals. Earlier in that campaign, the original test_complete_bounded_search called produce(4) and passed its in-memory return directly to verify_document. The archived historical-v1627.log records that test passing. The verifier reads first_witness, validates both event paths, and returns four totals and one digest. This locates an executed reader of individual event data beyond the comparison of totals. The earlier test and later file-producing command run in separate processes. The follow-up passes the archived log document to the unchanged verifier five times under the initial scope, then tests a sixth input supplied independently in the agent thread. It holds every outer summary field fixed. Each call executes the full historical four-site enumerator. The reader reconstructs the next state from the current state, chart index and site, then computes the global height increment. It also checks the shared endpoint, increment sum and which addressed increments differ across the two paths. [Original verifier](https://github.com/proteinfoldingengine/WetLabEngine/blob/e61d5b0e827f7b412824ad46021e2ad6cc6f7875/ResearchHistory/UQCF-GEM/demos/v16.27-increment-attribution-closure/verify.py#L13).

The original v16.26 per-atom verifier rejected all four reversed triggers individually. Thus a field can be retained in a genuine receipt, and meaningful to its originating validator, yet omitted by the downstream historical path check. The comparison that read the saved file used four totals. The older per-event verifier returned a global validation summary. Neither inspected operation posts a receipt to a chart or changes that chart's retained view. The mutations are this follow-up's tests, independent of the historical transcript. The sixth input implements the [independently proposed witness replacement](https://github.com/proteinfoldingengine/WetLabEngine/pull/111#issuecomment-7208613338). Its initial two charts both hold {0,1,2}. Each releases a different leaf, in either order. The original atom produces all four alternative receipts, and the original witness constructor accepts the addressed change. A direct scan of all original four-site endpoint cases confirms the repeated starting row was outside that campaign. Replacing only the logged witness with this different legal witness still returns the identical summary and digest. The validator checks the submitted paths and the regenerated campaign summary separately. A passing verdict alone cannot tie a witness to the original run. Provenance for the genuine four rests on their separately traced production, serialization and exact archived bytes.

A second source check searched the 1,548 tracked UQCF Python files at the same historical SHA for literal first_witness. The only matching files were the v16.27 engine and verifier.
