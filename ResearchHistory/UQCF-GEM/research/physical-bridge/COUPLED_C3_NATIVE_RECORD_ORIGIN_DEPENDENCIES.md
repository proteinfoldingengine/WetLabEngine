## Finding
The inspected constructions reduce the information required for control but do not, in these sources, construct all of that information from an already accessible native input. Three distinct obligations must remain separate:
1. initialization and accessibility of a retained description;
2. enforcement of the admissible transition relation;
3. selection and retention of the actual resolved outcome.

A mathematical state projection, an exact legality algorithm supplied with sufficient data, and an actual record are different objects. Composing their conditional results does not erase their input premises. This is a dependency finding over the listed sources, not an archive-wide impossibility result.

## Executable boundary
In core_readout/producer.py, supports(s) reads all five bits, including hidden x,y. produce() enumerates every candidate, computes tau on its full supports, filters the admissible state IDs using full support sizes and tau, and admits toggle edges by membership in those IDs. Its projected fibers are subsequently grouped by s[2:].

This is appropriate for a full-state verification oracle. It is not an implementation that obtains legality using only the observer's current core record. The successful exhaustive graph checks therefore do not discharge native enforcement or record initialization.

In v15.11/ontology_continuity_audit.py, pinch takes supplied projectors. select_record takes an explicit integer record and raises ValueError when that record is omitted. Positive weight is checked after the supplied selection. This code preserves the conditional actual-record construction; it does not select an actual record autonomously.

No code defect follows from either observation. Their declared conditional purposes are consistent with these inputs.

## Known obstructions are not new discoveries
At the core-readout baseline, hidden 00 and 11 have identical visible core. The bridge addition is admissible for 00 and inadmissible for 11. This is already a published control. Applying the existing observation-fiber criterion again does not produce a new theorem. It only explains why the current core record alone cannot implement an exact maximally permissive decision for this request. An always-rejecting policy remains safe and uninformative.

A12.5 already gives different candidate legality with identical entire candidate overlap component, palette size, root count and current tau. Its scope is that particular raw-overlap information interface. It does not exclude every internal enforcement mechanism, every enlarged retained channel or physical locality.

Similarly, allowing NOOP forever already blocks guaranteed readout completion. Rephrasing that fact as record-origin impossibility would add no mathematical information.

## Next construction required
A useful next proposal must name a concrete native input domain I and give explicit maps or relations for:
- initializing an observer-accessible retained record r from I;
- processing a typed request using available retained/local information;
- enforcing the permitted full-state outcomes while keeping any system-side information distinct from observer-accessible information;
- recording the actual outcome through an explicitly available retained update.

For each input field, cite its earlier construction or label it as an added assumption. In particular, system-side guard access is not automatically observer access, and an external full-state verifier is not a derived native guard.

Check the proposal on the existing 00/11 bridge pair: show exactly what native relation distinguishes their admissibility and how that relation is available without assuming the desired observer readout. If an initialized miss-count field is used, its initialization is the open obligation, not a completed step. If actual selection is used, preserve the RCR boundary rather than silently deriving it from a set of possible successors.

This is a specification for further research, not an assertion that such a construction exists. No new finite campaign is warranted until a candidate supplies those maps and its premises.
