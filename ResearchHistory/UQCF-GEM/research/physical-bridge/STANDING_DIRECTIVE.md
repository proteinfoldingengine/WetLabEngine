## 1. Scientific mission

The objective is not to accumulate additional conditional mathematical theorems.

The primary objective is: derive one native informational interaction in which a source difference necessarily produces an accessible consequence without inserting the interaction, observation mechanism, or outcome law by hand.

A successful result may be deterministic or probabilistic. It need not explain gravity, unify physics, or guarantee that every possible event completes.

It must demonstrate a genuinely derived connection between:
1. an existing native informational distinction;
2. a justified interaction or update rule;
3. an actual retained consequence or derived outcome distribution;
4. an identifiable receiver with justified access;
5. a mathematically established separation between the original preparations.

Do not mistake mathematical admissibility for physical enforcement, an available event for an actual event, or an ensemble average for a single realized record.

A fresh context from the same authoring agent is a self-check, not independent review. Use the repository's existing GitHub Actions integration with Gemini. The previously working text-review model was gemini-3.1-pro-preview; verify availability first and do not repeatedly retry models known to fail. Ask the reviewer to independently reconstruct the proof, identify missing assumptions and circular definitions, search for explicit counterexamples, challenge the physical interpretation, identify any mechanism, orientation, reader, or event law inserted by assumption, distinguish valid mathematical conclusions from unsupported physical claims, and return ACCEPTED, REVISE, or FAIL.

Preserve the raw response, model identifier, workflow run ID, reviewed commit SHA, response hash, and findings. ACCEPTED is evidence of independent analytical review, not empirical validation or physical truth.

## 4. Make GitHub the scientific verification system

**Branches and commits:** keep Path-A work on the research branch; make every checkpoint traceable to an immutable commit; never silently change a frozen proof or test contract after verification; substantive corrections need a new commit and fresh verification.

**GitHub Actions:** separate jobs for source integrity and prerequisites; mathematical proof and independent computational reconstruction; rejecting controls and inherited regression tests; independent Gemini review; independent publication consistency audit; immutable final readback. Gate downstream review on successful verification of the exact source commit. A successful workflow without a valid mathematical verdict is not scientific acceptance.

**Independent verification:** for new bounded claims, use independently implemented producer and checker logic, where the checker does not call the producer's decision functions; enumerate the complete prospectively declared finite universe where feasible, including rejected cases; preserve counterexamples and failures; do not adjust thresholds, domains, or assumptions after unfavorable outcomes without recording and reviewing the change.

**Artifacts and provenance:** retain original ZIP archives, complete workflow logs, raw reviewer responses, test manifests, source hashes, and publication receipts; verify byte lengths, SHA-256, git blob identities, and source commit relationships; GitHub history, Actions artifacts, and immutable readback are the authoritative trail.

**PRs and checks:** use a draft PR when useful to compare a substantial checkpoint with its verified parent; require integrity, verification, and review gates before closeout; do not merge into the default branch unless separately authorized.

## 5. Strict research admission gate

Before a new major investigation, answer what currently missing native mechanism the candidate could actually derive. Each checkpoint must identify the precise unsolved obligation, the existing native primitives used, the new deduction that might follow, the strongest known counterexample, the accessible consequence to be tested, and the assumptions that would invalidate a physical interpretation.

Classify:
- **A** — Native mechanism candidate: a credible path to deriving interaction, retained output, or receiver access from existing primitives.
- **B** — Necessary mathematical support for an A candidate.
- **C** — Conditional illustration after supplying a mechanism.
- **D** — Repetition or an already closed obstruction.

Prioritize A, pursue B only in support of a specific A, document C briefly, and do not launch expensive verification for D. A negative result is valuable when it eliminates a genuinely plausible mechanism or a sharply scoped new boundary; do not manufacture progress through variations of understood obstructions.
