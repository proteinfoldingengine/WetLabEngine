# Source-withdrawal completion forces a descendant record

Constructive continuation, 2026-10-17. Analytical working construction with a focused internal mathematical/interface check. It has not received independent Gemini acceptance and does not establish native physical closure. No code or scientific execution was used.

## Result first

An actual occurrence of one specified native source deletion can force a previously blank descendant record, without separately assuming that the receiver takes a proper step.

Use a common rooted chain `o→u→v` and palette `P={a,b₀,b₁}`. The source support at `u` is `{a,bₛ}`; the receiver support at `v` is initially `{a}` in either source preparation. The same source event in both worlds withdraws `a` at the same vertex `u`.

After any committed occurrence of that source event, nonemptiness and nesting force the receiver support to be exactly `{bₛ}`. The receiver cannot remain idle at `{a}`. A legal native completion exists:

    +bₛ(v), −a(v), −a(u).

This is a completion relation, not forward-time propagation from the final deletion. The receiver adjustment must precede the source commit. The conclusion holds for every lawful completion of that source event, not only for the displayed shortest path. There is no separate minimum-completion law, hidden response condition, copying operation, receiver fairness assumption, or source-sensitive command supplied to the receiver.

The displayed `+b_s(v)` is a branch-indexed existence witness, not an executable instruction available to a blind receiver. There is no common nontrivial legal initial receiver edit in the two preparations. The construction derives the consequence of source-event completion; it does not supply a blind policy that completes that event.

The precise remaining native interface is actual enactment/ownership: an already realized source event must be connected to this committed support-withdrawal semantics, and `v`'s retained support must be an available receiver record. The allowed-edit grammar alone does not invoke its own transitions or deliver their coordinates.

## 1. Exact native state and interface

The inherited nested-support carrier has a fixed finite rooted tree `T` and a finite nonempty palette `P`. Its native states satisfy

\[
S_o=P,\qquad \varnothing\ne S_x\subseteq P,\qquad
S_y\subseteq S_x\quad\text{when }y\text{ is a child of }x. \tag{1}
\]

A primitive adds or deletes one label incidence at one nonroot vertex while preserving (1). The root, palette, and structural identities stay fixed. These are the existing definitions, with no extra band, floor, simultaneous edit, or response kernel.

Use

\[
T=\{o,u,v\},\quad o\to u\to v,\qquad P=\{a,b_0,b_1\}.
\]

The two preparations are

\[
S_o=P,\qquad S_u=\{a,b_s\},\qquad S_v=\{a\},
\qquad s\in\{0,1\}. \tag{2}
\]

Both are legal states. The root and actual lineage identities are the same in both. Only the source coordinate at `u` differs. No amplitude, signed source vector, quantum factorization, cross-Genesis identification, or metric is needed.

The receiver interface for this construction is the vertex-local retained record

\[
\mathcal R_v(S)=(\text{common reference data},S_v). \tag{3}
\]

The common data may contain the rooted tree, palette, and the same named `u,v,a,b₀,b₁` references. They do not include the support `S_u` or any other answer-bearing source field. The initial interface in (3) is exactly identical for both preparations, not just equal under one chosen statistic.

This is an explicit change from the previous draft's label-owned complete-view interface. Here the receiver is a vertex-local support record. The transpose `S_v={i:v∈Y_i}` gives a canonical mathematical coordinate on the same native incidence object, but does not prove that an owner of one complete view `Y_i` can read that row. Nor does a receiver's knowledge of the address of its ancestor `u` give it knowledge of `S_u`.

No initial legality oracle, success notification, or source-dependent transition rate is included in (3). Such an oracle could disclose additional information and must not be silently granted. The question is acquisition in the receiver's stored local record, not indistinguishability under every future possible interaction with the source.

## 2. Specify the source event without specifying the receiver answer

In both preparations the named source event is exactly

\[
E=-a(u):\quad\{a,b_s\}\longrightarrow\{b_s\}. \tag{4}
\]

The label being withdrawn and the source address are identical in both worlds. The event does not name the value of `s`, a receiver action, a receiver readout, or a particular completion path.

For the strongest interim-readout statement, consider all finite native histories starting from (2), allowing arbitrary legal receiver edits at `v`, keeping the source support at `u` fixed until the distinguished event (4), and ending immediately after a committed occurrence of (4). Fixing `S_u` throughout the prefix is an explicit preparation-preservation condition; it ensures that an informative intermediate receiver record cannot report the wrong branch.

The final singleton conclusion needs less: the source state immediately before the distinguished event need only be exactly `{a,b_s}`, and the event must delete `a` there. Even if earlier source changes occurred, every admissible immediate endpoint of that event still has `S_v={b_s}`. Specifying this source-event input is not a condition on the desired receiver output.

The interval can contain arbitrary admissible backtracking. No receiver scheduler, shortest-path preference, or policy selecting a label is part of this completion class. In a larger carrier, independent edits elsewhere may be included as long as they preserve the specified source-event input and the ordinary native constraints.

## 3. The source event forces the receiver endpoint

Immediately after (4), `S_u={b_s}`. By native nesting and nonemptiness,

\[
\varnothing\ne S_v\subseteq S_u=\{b_s\}.
\]

Therefore

\[
S_v=\{b_s\}. \tag{5}
\]

This proves the endpoint for every lawful completion, without assuming any proper receiver step in the conclusion's premises. Keeping the initial `S_v={a}` would violate nesting after the source event. The source bit has remained at `u` and is now also present at `v`; no global creation of information is asserted.

The receiver decoder is simply

\[
D(\{a\})=\bot,\qquad
D(\{a,b_s\})=s,\qquad
D(\{b_s\})=s. \tag{6}
\]

While the source support stays `{a,b_s}`, every receiver state is a nonempty subset of that set. Hence the decoder never returns the wrong branch anywhere in this completion class. A record containing `b_s` is already an informative record even before the source event commits. Equation (5) says that source commitment guarantees such a record and removes the common blank label.

The receiver record is not a receipt proving that (4) has already happened: it can acquire `b_s` earlier. It witnesses acquisition itself. No source-event acknowledgment is needed for reading the source bit from the record.

## 4. Construct a complete lawful path

The following path proves nonempty completion fibers in both source cases:

\[
\begin{array}{c|c|c}
&S_u&S_v\\\hline
\text{initial}&\{a,b_s\}&\{a\}\\
+b_s(v)&\{a,b_s\}&\{a,b_s\}\\
-a(v)&\{a,b_s\}&\{b_s\}\\
-a(u)&\{b_s\}&\{b_s\}.
\end{array} \tag{7}
\]

Each step changes exactly one existing native incidence:

- The addition at `v` is legal because its parent `u` already contains `b_s`.
- The receiver deletion is legal because `b_s` keeps `v` nonempty and `v` is a leaf.
- The source deletion is legal because its child no longer contains `a`, and `b_s` keeps `u` nonempty.

No response coefficient or output value was inserted into the update grammar. The source's existing upper support determines which replacement label is permitted at the receiver.

In the initial receiver state `{a}`, deletion of `a` is forbidden by nonemptiness. The only legal nontrivial receiver edit is `+b_0(v)` in source case 0 and `+b_1(v)` in source case 1. These legal initial edit sets have empty intersection. Accordingly, the path in (7) certifies existence separately in the two native states; it is not a source-blind executable instruction. A policy that tests candidate edits, obtains their legality, or retries until one succeeds would need an additional earned invocation/feedback interface.

The order has a structural meaning. Deleting `a` from `v` first would empty it. Deleting `a` from `u` before removing it below would violate nesting. Thus every completion must have introduced `b_s` at `v` and removed `a` there before the source commit. The three-edge path is a witness to that required handoff, not a new law insisting that nature choose this path or its length.

On this chain every internal vertex has one nonempty child support, so every local hitting number is one throughout. The common all-one target profile is therefore maintained exactly. No diagnostic count or externally imposed guard is responsible for the transfer.

The general native finite-prefix category permits unary vertices. If a separately bounded normalization theorem restricts arity, this chain theorem does not borrow that theorem or extend its arity claim.

There is also a fully binary witness. Give `o` children `u,z` and give `u` children `v,w`. Set

\[
S_o=P,\quad S_u=\{a,b_s\},\quad S_z=\{b_0,b_1\},
\quad S_v=S_w=\{a\}.
\]

The same source event is `−a(u)`. One completion is

\[
+b_s(v),\quad +b_s(w),\quad -a(v),\quad -a(w),\quad -a(u).
\]

Every committed endpoint forces both `S_v=S_w={b_s}`. At `u`, the children share `a` throughout the additions and share `b_s` throughout the deletions. At `o`, the unchanged support at `z` intersects `S_u` through `b_s` throughout. Thus both internal hitting numbers remain one. The extra branch supplies no source-specific input to the receiver: `S_z` and the entire initial descendant pair are common across preparations.

## 5. Joint retained-view composition of the same object

The corresponding views are obtained by the earned literal transposition

\[
Y_i=\{x:i\in S_x\}.
\]

Initially,

\[
Y_a=\{o,u,v\},\quad Y_{b_s}=\{o,u\},\quad
Y_{b_{1-s}}=\{o\}.
\]

At the source-event endpoint,

\[
Y_a=\{o\},\quad Y_{b_s}=\{o,u,v\},\quad
Y_{b_{1-s}}=\{o\}. \tag{8}
\]

Their union remains `T` throughout (7). The initial source distinction is internal to the `b`-view; the receiver coordinate is the leaf row at `v`, which initially lacks both `b` labels. The transfer supplies the exact alternate coverage before `a` is removed. A separate universal keeper or an independent physical memory is unnecessary in this construction.

The `b_s` addition extends a view; the subsequent `a` deletions prune a view. This uses the native reversible addition/deletion grammar and is not falsely described as deletion-only evolution of every indexed view. The associated source event (4) is a pruning operation. The whole completion is an ordered combinatorial path, not a duration or a fundamental clock.

This construction is also not a central-sector view family from the earlier draft: the initial `Y_{b_s}` ends at the internal vertex `u`, so it need not equal any `V(p)` in a laminar central-sector tree. No new identification of a support label with a central projector is made. The positive forcing mechanism here is native support nesting and nonemptiness.

Actual retained-subview compositions and the overlap gluing theorems continue to apply where their types fit. They make the resulting carrier and comparison maps coherent; they do not select or invoke the native completion. No source-field reconstruction is needed to define or read (5).

## 6. A receiver subtree, not just one leaf

Let `D` be the entire finite nonempty strict-descendant cone below `u`, and initialize

\[
S_x=\{a\}\quad(x\in D)
\]

in both source preparations. Keep the same source support and same event (4). At every endpoint with that event committed, repeated nesting gives

\[
\varnothing\ne S_x\subseteq\{b_s\}
\quad\Longrightarrow\quad S_x=\{b_s\}\quad(x\in D). \tag{9}
\]

Thus every receiver vertex, or the entire initially common descendant subarray, records the source bit at completion. Fine details of the intervening history remain unresolved without affecting this consequence. The endpoint implication itself applies to any selected descendants by repeated nesting; the entire-cone initialization is needed for the following explicit all-one-profile completion witness.

A lawful completion adds `b_s` at all descendants in parent-before-child order, then removes `a` at all descendants in child-before-parent order, and finally removes `a` at `u`. During the addition phase every child support still contains `a`; after all additions every child support contains `b_s`, which remains throughout deletion. Hence all local hitting numbers can stay one even on arbitrarily branching descendant trees. The argument uses the inherited native grammar, not a new selected schedule as a physical rule.

While the source support remains `{b_s}` and the receiver carrier remains retained, native nonemptiness and nesting force (9) in every later state. Persistence then follows from the same constraints. A later expansion or replacement of the source support is a different operation and requires its own retention analysis.

## 7. Exactly what occurrence has been earned

The preceding branch-record draft assumed a proper receiver refinement and derived its branch. This completion result removes that independent receiver-step premise: a committed source withdrawal with the specified input forces receiver acquisition, including the necessary earlier receiver changes.

This is stronger than selecting a favorable allowed receiver endpoint. The same source command is used in both preparations, and every legal completion has the claimed receiver record. It is not yet a derivation that a source request must commit.

In the initial state (2), the source command `−a(u)` is not an enabled atomic transition. Its lawful completion exists, but a request can remain pending or produce no change under an execution interface that permits that behavior. The event (4) cannot be placed first and followed by a supposed forced repair: that would pass through a state forbidden by the very native relation used in the proof.

Accordingly this is an atemporal joint-completion implication:

\[
\text{specified source withdrawal has committed}
\quad\Longrightarrow\quad
\text{receiver has the source branch record}. \tag{10}
\]

It is not a later-in-time influence from the final deletion to an earlier update. Nor does it assert that any fair scheduler, measurement, or response law has been derived. Conditional on an actual committed source event, all probability distributions over lawful completion histories give the same exact receiver branch. No separate receiver success probability is needed under that conditioning.

The probability reduction can also be stated without conditioning the readout on a completion acknowledgment. Consider any specified ensemble of finite lawful history prefixes, each ending before or immediately after the distinguished source commit, with `S_u={a,b_s}` fixed until that commit. Let `p_s` be the probability that (4) has committed, and let `q_s` be the probability that the local decoder has an informative value. Then

\[
q_s\ge p_s,\qquad
\Pr(D=s\mid s)=q_s,\quad
\Pr(D=\bot\mid s)=1-q_s,\quad
\Pr(D=1-s\mid s)=0.
\]

The receiver's two output laws have total variation distance `max(q_0,q_1)`, hence at least `max(p_0,p_1)`. With a balanced source prior, the mutual information is at least `(q_0+q_1)/2` bits and therefore at least `(p_0+p_1)/2` bits: a nonblank output determines the source, while a blank output has at most one bit of conditional entropy. In particular, a native lower bound `p_s≥ε>0` would imply at least `ε` bits of receiver information. No positive `p_s`, sampling law, stopping protocol, or physical clock is supplied by this proof.

## 8. The single native realization interface still needed

At the level of the admitted support-state category, the completion relation, nonempty paths, forced endpoint, source-independent event identity, and initially blind local record are explicit. No further mathematical composition is required to determine the receiver answer.

The remaining interface is a native realization of that incidence-state operation and record:

    actual source-event record
        → committed withdrawal on the identified retained support object
        → available local support record at the identified receiver vertex.

The first arrow must connect a real source event to the meaning of `−a(u)` and the source support it acts on. The second must identify who retains and can access `S_v` or the descendant subarray. They are the action and readout faces of one missing source-event-to-owned-retained-state interface. An arbitrary map from an existing event ID to the desired incidence command would not earn it.

The inherited certified source-binding record `(genesis, provenance root, source event, full lineage address)` already types event localization. It does not, in its inspected definition, specify a label-incidence withdrawal or receiver access. Conversely, the native support grammar specifies exactly what a lawful edit does, but contains no operation that creates the source-event binding, invokes the edit, or transmits its coordinate to an owner.

An earlier retained record of the same history could supply the receiver carrier without an independent physical subsystem: its address can remain fixed while its local retained state changes. But merely retaining that address or an earlier value does not derive writable row storage or delivery of its updated support. This remains a concrete realization target, not a requirement to invent another quantum carrier.

Overlap gluing maps already compatible local data to a joint mathematical object; atomic factorization maps a chosen endpoint relation to allowed paths. Neither has the missing type of an actual event-to-owned-record implementation. This is why the exact endpoint proof does not yet establish the native physical milestone. It is not a claim that such an implementation is impossible.
